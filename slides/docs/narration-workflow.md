# Narrated Slidev workflow

This project uses one narration manifest for two outputs:

- live Slidev playback, where the deck advances after each narration segment;
- a deterministic 1920x1080, 30 fps H.264/AAC MP4 assembled from captured slide states.

Run the commands below from the `slides/` directory. FFmpeg (including `ffprobe`) and the
project's pnpm dependencies must be available locally.

## Daily commands

Validate the YAML, audio paths, audio durations, and page/click ordering without rewriting
the compiled timeline:

```bash
# Validate source files
pnpm narration:validate
```

Regenerate the timeline, then preview automatic playback in Slidev:

```bash
# Preview automatic playback
pnpm narration:build
pnpm dev
```

Open the URL printed by Slidev and click **Start narration**. The user click is required by
browser autoplay policies: it unlocks audio playback before the controller starts advancing
the deck. Narration never starts automatically on page load.

Validate, compile, capture every referenced state, render, and inspect the final file in one
command:

```bash
# Render final video
pnpm narration:video
```

The capture command starts and stops its own loopback Slidev server. A separate `pnpm dev`
process is not required for `pnpm narration:video`.

If only the Remotion composition styling changed, reuse the existing PNG captures:

```bash
# Re-render only after changing Remotion styling
pnpm narration:render
pnpm narration:inspect
```

`narration:inspect` prints a JSON pass/fail report and exits non-zero unless the MP4 has
exactly one H.264 video stream and one AAC audio stream, is 1920x1080 at 30 fps, and is
within 100 ms of the compiled timeline duration.

The final video is written to:

```text
dist/narrated-slides.mp4
```

`pnpm build` rebuilds the Slidev site into the same `dist/` directory and can remove the
MP4. When checking both outputs, run `pnpm build` before `pnpm narration:video`. If a later
Slidev build removes an otherwise current MP4, restore it from the existing captures with
`pnpm narration:render` followed by `pnpm narration:inspect`.

## Editing the narration manifest

`narration/script.yaml` is the source of narration order and timing.
`narration/generated/timeline.json` is generated by `pnpm narration:build`; do not edit it
by hand.

`click: 0` is the state visible immediately after entering a slide, before any click reveal.
Later values (`click: 1`, `click: 2`, and so on) identify the state after that many Slidev
click advances. Every slide represented in the manifest starts with a `click: 0` segment,
and clicks must be strictly increasing.

A narrated segment uses one audio file:

```yaml
- id: architecture-intro
  click: 0
  text: 'This slide introduces the architecture.'
  audio: narration/audio/s003-c000.mp3
```

Keep audio under `public/narration/audio/`. Use stable names such as
`s003-c000.mp3`, where the page and click are zero-padded to three digits. The filename is
a convention for reviewability; the manifest path is authoritative. Paths are relative to
`public/`, so do not add a `public/` prefix.

To hold a state without speech, use `silentMs` instead of `audio`:

```yaml
- id: architecture-pause
  click: 1
  text: ''
  silentMs: 1200
```

Every segment must contain exactly one of `audio` or `silentMs`. A silent segment still
receives the configured transition, lead-in, and tail timing. Use `silentMs: 0` when a
click state must be explicit but needs no additional hold.

After changing narration text, audio, timing, or click mappings, run at least:

```bash
pnpm narration:validate
pnpm narration:build
pnpm narration:capture
pnpm narration:render
pnpm narration:inspect
```

`pnpm narration:video` is the equivalent one-command path.

## What must be recaptured

The first release renders static state screenshots. Playwright loads each referenced
`(page, click)` independently and captures one 1920x1080 PNG. Remotion displays those PNGs
and applies deterministic crossfades; it does not run the Slidev application during MP4
rendering.

Run `pnpm narration:capture` again after changing anything visible inside a captured slide,
including:

- slide content or layout;
- theme, Slidev CSS, fonts, icons, or image assets;
- click-reveal content or the page/click mapping;
- embedded content whose captured appearance changed.

Arbitrary Vue/Slidev motion between click states, live iframes, video playback, cursors, and
other runtime interactions are not reproduced offline. They appear only as the static state
seen at capture time. The MP4 transition between states is the Remotion crossfade, not the
original Slidev animation.

Changing only Remotion-side presentation—such as crossfade treatment, canvas background, or
composition styling—does not change the source PNG pixels. In that case,
`pnpm narration:render` followed by `pnpm narration:inspect` is sufficient.

## Review gate

Media inspection proves stream layout, codecs, dimensions, frame rate, and total duration.
It does not prove that spoken words match the visible slide. Before publishing real
narration, watch the first segment, a same-slide click, a slide-to-slide transition, a silent
segment, and the final segment.

The repository's current two-slide sample uses short tone files as deterministic pipeline
fixtures. Tones can prove audio placement but cannot support a semantic spoken A/V review.
Replace them with genuine speech and expand the manifest before treating the result as a
finished narrated deck.
